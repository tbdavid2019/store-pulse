# Proposal

## Why

Store Pulse 目前透過 Google Places 顯示最多 10 家分店及每店最多 5 則評論，管理者仍需逐則閱讀才能找出近期服務問題。沿用已取得的 Places 評論並整理成帶原文依據的摘要，可避免新增評論擷取服務，並以小規模試接驗證資料品質與模型費用。

## What Changes

- 新增由使用者點擊觸發的單店深度分析，支援近期評論與低分評論兩種取樣方式，預設分析近 90 天，可切換近 30 天。
- 新增分析 API，接收搜尋分店時 Google Places Details 已回傳的最多 5 則評論，保留評論時間、分店來源與取樣資訊；不再額外購買評論擷取服務。
- 產出繁體中文營運摘要，聚焦服務、等待時間、商品品質、環境與價格；每項結論連結評論證據，呈現樣本限制及評論誘因訊號。
- 提供共用快取、每次分析請求上限、每日額度與錯誤處理，讓外部服務費用可控。
- 第一階段採用單店分析；多店比較、定期監控、通知、照片辨識與個人金庫列為後續工作。

## Capabilities

### New Capabilities

- `review-evidence`: 店家身分核對、評論擷取、時間篩選、去重、證據溯源與受控用量。
- `store-review-analysis`: 使用者觸發分析、結構化營運摘要、證據檢視及失敗與空樣本狀態。

### Modified Capabilities

目前主規格目錄尚無既有 capability。

## Impact

- 前端：`index.html` 的分店卡片及分析狀態；`service-worker.js` 的分析 API 網路策略。
- 後端：Python API、模型 adapter、持久化快取與每日模型呼叫額度；前端需將已取得的分店評論樣本送入 API。
- 部署：提供本地同源服務及靜態前端搭配 HTTPS API 的設定；既有 Hugging Face static hosting 需搭配獨立 API，部署平台在試接前確認。
- 外部依賴：可設定的文字模型服務；金鑰由後端管理，Google Places 評論沿用搜尋分店時已取得的資料。保留 TLDReview MIT 授權及來源資訊。
- 驗收：以 3 家可核對的分店試接，記錄身分匹配、評論期間、摘要證據、延遲及實際 API 用量；本變更先建立規劃文件。
